# Цель: регулярные данные Авито, Циан и Домклика

## Критерий выполнения

Источник считается подключённым только после успешного ежедневного запуска в GitHub Actions: объявления действительно получены, география и арендные поля проверены, источник и время сохранены, ошибки не удаляют прежний каталог. Установка библиотеки или статический снимок не считаются регулярным сбором. ИИ не участвует в сборе, извлечении полей или финансовых расчётах.

## Текущее состояние

- Авито: реализованы XLSX/CSV/JSON Duff89 и чтение JSON из публичного MFE-состояния HTML (`mime/invalid`, `data-mfe-state`). Безусловная ошибка после успешного HTTP заменена разбором распознанного каталога и публичной пагинацией. Публичные запросы в среде проекта возвращали недоступность/404. Работающий регулярный поиск чужих коммерческих объявлений не подтверждён; тесты формата не считаются живым сбором.
- Циан: коммерческий адаптер публичного HTML написан и проверен на полученных страницах. Из GitHub Actions приходила защитная страница. Опубликованный снимок датирован и не выдаётся за автоматически обновляемый источник.
- Домклик: добавлены нативные JSON/CSV (`result.items`, `items`, `offers`, модель Offer) и экспериментальный декодер JSON-состояния HTML. Формат экспорта сверялся с Ho1ocron/parses-domclick, commit `18d26bce4d95465a482233afa6e6b0c04c219666`. Реальная HTML-разметка и живой сбор не подтверждены: обычная публичная страница вернула HTTP 401 с защитной проверкой. Подписи приватного мобильного API и обход TLS не используются.

## Дополнительные проверенные направления

Повторная проверка 16 ноября: изучены ещё 11 репозиториев, у пяти выполнены функции извлечения на настоящих ответах сайтов. Обычный локальный сбор ЦИАН получил 162 объявления на 6 страницах и отобрал 37 кандидатов; GitHub Actions снова получил защитную страницу. Подробности и границы испытаний: [протокол](parser-trials-2026-11-16.md). Разовый сбор не объявляется регулярной интеграцией.

1. https://github.com/MissiaL/avito-api — изучены README и раздел item. Это справочник официального Business API: управление опубликованными объявлениями, статистика и услуги владельца аккаунта. Раздел item не предоставляет подтверждённый поиск всех чужих предложений рынка. Наличие OAuth-ключа само по себе задачу не решает; запрос новых полномочий без подходящего endpoint не обоснован.
2. https://github.com/Ho1ocron/parses-domclick — изучены README, browser.py и parser.py. Альтернативная реализация использует Selenium, сессию браузера и служебный web API. Это не доказательство стабильного или открытого доступа из нашей инфраструктуры; обход текущей защитной проверки не подключён.
3. Подключённый каталог плагинов проверен: подходящий коннектор для Авито/Циан/Домклика не найден. Нерелевантные приложения не предлагаются.
4. Официальная документация https://public-api.cian.ru/docs/latest: `GET /v2/get-my-offers` получает объявления агентства, которому выдан ключ. Это не API поиска предложений всего рынка. Ключ агентства сам по себе не устраняет препятствие.
5. Подключена отдельная публичная витрина РБН https://kazan.rbnpro.ru/rents/show_all . Проверены robots.txt и реальные карточки. Витрина содержит Казань и Зеленодольск; явные предложения будущей сдачи и обычные помещения без арендной модели отбрасываются. МАП не выводится из рекламной окупаемости. Это дополнительный источник, а не выполненная интеграция трёх площадок.
6. Metrapi: https://metrapi.ru/api-docs.html заявляет все три площадки и коммерческую недвижимость. По https://metrapi.ru/offer.html API входит в платный доступ; пункт 6.1.4 требует письменного согласия на публикацию данных и производные сервисы. Для публичного InvestScan обычной подписки недостаточно. Аккаунт не создавался, услуги не покупались, ключи не запрашивались. Подготовлен [технический запрос об условиях](provider-inquiry.md), он не отправлен.

## Защита достоверности импорта

Импорт не становится `ok`/живым сбором: в отчёте отдельно `live_count`, `imported_count` и `invalid_count`. Старый или недатированный импорт не перезаписывает более свежее наблюдение по той же ссылке. Повтор неизменённого файла не меняет дату наблюдения и историю. Неизвестное время источника остаётся null, время чтения файла отдельно. Файловый mtime не используется: новый checkout GitHub Actions не делает данные свежими. Неверная запись не мешает обработать остальные. При утрате SQLite сначала восстанавливается опубликованный каталог, затем применяются обновления; даты источника при восстановлении не меняются.

## Следующие допустимые пути

- Проверенный официальный/партнёрский канал чтения рыночных объявлений с документированными правами и географией, если площадка предоставляет такой доступ.
- Разрешённые выгрузки владельцев/агентств, сохраняющие исходные ссылки площадок и время получения. Это обозначается как фид/выгрузка, не как прямой парсинг всей площадки.
- Обычная обработка открытых страниц, если доступ существует без защитной проверки. Изменение разметки устраняется адаптером и тестами, а не выдуманными данными.

Платные сервисы и новые аккаунты без согласования не подключаются. CAPTCHA, авторизация, защитные блокировки и приватные подписи запросов не обходятся. Цель пока не выполнена для всех трёх площадок.
